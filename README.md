# تطبيق إشارات السوق

تطبيق Android للمستخدمين، ولوحة إدارة ويب أولية في `admin/`، وخدمة خلفية
FastAPI/PostgreSQL في `server/`. النظام معلوماتي فقط: لا ينفّذ صفقات ولا يطلب
مفاتيح تداول من المستخدم.

## وضع المشروع

- واجهات Android عربية تشمل التسجيل وتأكيد البريد، الإشارات، العملات والبحث،
  الأخبار، الحساب، ساعات جلسة لندن بالتوقيت المحلي، تفاصيل الصفقة وتسجيل دخول
  المستخدم إليها.
- لوحة الإدارة الأولية تعرض المستخدمين والإشارات، وتتيح تمديد الوصول يدوياً
  وإدارة حد الإشارة والمنصات المدعومة. تُقدَّم من الخادم على `/admin/`.
- الخادم يقرأ بيانات السوق العامة من Binance Futures وBybit وOKX، وينشر فقط
  إشارات توافق فني بدرجة 65/100 فأعلى. هذه الدرجة ليست احتمال ربح.
- لا يعرض التطبيق أسعاراً أو إشارات تجريبية عندما لا يكون الخادم مضبوطاً.
- تتطلب تجربة التطبيق عنوان خادم HTTPS مضبوطاً في GitHub Actions بمتغير
  المستودع `API_BASE_URL`. بعد نشر الخدمة على VPS، أضف هذا المتغير في
  `Settings > Secrets and variables > Actions > Variables`.
- انظر [تعليمات الخادم والنشر](./server/README.md) لإعداد Docker Compose وVPS.

## البناء السحابي

يجهّز `.github/workflows/build.yml` Java 17 وFlutter وPython على GitHub Actions،
ويفحص لوحة الإدارة، ويشغّل اختبارات الخادم والتحليل واختبارات Flutter، ويولّد
Android مع `minSdk = 21`، ثم ينتج APK.
يفعّل `FLAG_SECURE` لمنع لقطات الشاشة/التسجيل المعتاد في Android، لكنه لا
يمنع التصوير بجهاز خارجي أو يتجاوز جهازاً مخترقاً.

نزّل APK الناجح من **Artifacts** في تشغيل GitHub Actions. البناء الحالي غير
موقّع بمفتاح توزيع إنتاجي؛ يلزم إعداد توقيع إصدار آمن قبل النشر العام.

## ملاحظات المنتج والسلامة

- درجة الإشارة هي درجة توافق فني من 100، وليست احتمال ربح أو ضماناً.
- يرفض الخادم نشر أي إشارة تقل درجتها عن 65/100.
- يحدد الخادم وحده انتهاء التجربة/الاشتراك؛ وقت الهاتف لا يمنح وصولاً إضافياً.
- يجب عرض مصادر الأخبار وروابطها، لا نسخ المقالات.
- بيانات التحليل عامة للقراءة فقط؛ لا تُستخدم مفاتيح خاصة ولا يُرسل أي أمر تداول.
- حظر لقطات الشاشة المعتادة عبر `FLAG_SECURE` ليس حماية مطلقة من جهاز خارجي أو
  نظام مخترق.
- يحتاج تأكيد البريد إلى إعداد SMTP على VPS. وإشعارات الدفع في الخلفية عبر FCM
  لا تُرسل بعد؛ الخدمة تحفظ أحداث الصفقة لكن لا تدّعي تسليم Push.
- يلزم إعداد قاعدة البيانات، سر JWT، البريد، HTTPS، حساب مشرف، وتوقيع APK
  بإعداد إنتاجي قبل إتاحة التطبيق للمستخدمين. مراجعة الاستراتيجية واختبارها
  تاريخياً وواجهة TradingView المضمنة ما زالا من أعمال المرحلة التالية.
