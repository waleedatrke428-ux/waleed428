# كريبتو البلحوسي

يتكوّن المشروع من تطبيق Android للمستخدمين، وتطبيق Android منفصل للمدير في
`manager_app/`، وخدمة خلفية FastAPI/PostgreSQL في `server/`. لا نعتمد لوحة ويب
للإدارة. النظام معلوماتي فقط: لا ينفّذ صفقات ولا يطلب مفاتيح تداول.

## وضع المشروع

- تطبيق المستخدمين يسجل الدخول ويتحقق من التجربة المجانية ذات الأيام الخمسة
  ويجلب الإشارات المحمية من خدمة FastAPI نفسها. واجهة PHP القديمة لا تدعم
  تسجيل الدخول أو الاشتراكات، لذلك لم تعد صالحة كمصدر للتطبيق.
- تطبيق المدير المستقل يعرض المستخدمين والإشارات، ويمدد الاشتراك شهراً بعد
  تأكيد العملية، ويضبط الحد الأدنى للتوافق ومنصات البيانات. يتحقق الخادم من دور
  المدير لكل مسار إداري.
- التطبيقان يحتاجان عنوان FastAPI واحداً منشوراً عبر HTTPS. عيّن متغير GitHub
  Actions `API_BASE_URL`، ويمكن تخصيص `MANAGER_API_BASE_URL` إن لزم؛ وإلا
  يستخدم تطبيق المدير `API_BASE_URL` أيضاً. من دون عنوان صالح يعرض التطبيق
  صفحة إعداد خادم بدلاً من محاولة الاتصال بخدمة PHP القديمة.
- خادم FastAPI يقرأ بيانات السوق العامة من Binance Futures وBybit وOKX؛ ملفات
  PHP القديمة لا تحتوي هذا الماسح ولا تنشئ إشارات تلقائياً.
- انظر [تعليمات الخادم والنشر](./server/README.md) لإعداد Docker Compose
  ومتطلبات استضافة API وقاعدة البيانات.

## البناء السحابي

يجهّز `.github/workflows/build.yml` Java 17 وFlutter وPython على GitHub Actions،
ويشغّل اختبارات الخادم والتطبيقين، ثم ينتج APK منفصلاً للمستخدمين وAPK للمدير.
كلاهما يستهدف `minSdk = 21` ويملك إذن الإنترنت. اسما التطبيقين **كريبتو
البلحوسي** و**كريبتو البلحوسي - المدير**. يفعّل كلاهما `FLAG_SECURE` لتقليل
لقطات الشاشة/التسجيل المعتادة؛ لا يمنع ذلك التصوير بجهاز خارجي أو نظام مخترق.

نزّل APK المطلوب من **Artifacts** في تشغيل GitHub Actions. البناء غير موقّع
بمفتاح توزيع إنتاجي؛ يلزم إعداد توقيع آمن قبل النشر العام.

## ملاحظات المنتج والسلامة

- درجة الإشارة هي درجة توافق فني من 100، وليست احتمال ربح أو ضماناً.
- يرفض الخادم نشر أي إشارة تقل درجتها عن 65/100.
- يحدد الخادم وحده انتهاء التجربة/الاشتراك؛ وقت الهاتف لا يمنح وصولاً إضافياً.
- يجب عرض مصادر الأخبار وروابطها، لا نسخ المقالات.
- بيانات التحليل عامة للقراءة فقط؛ لا تُستخدم مفاتيح خاصة ولا يُرسل أي أمر تداول.
- حظر لقطات الشاشة المعتادة عبر `FLAG_SECURE` ليس حماية مطلقة من جهاز خارجي أو
  نظام مخترق.
- يحتاج تأكيد البريد إلى إعداد SMTP على VPS. وإشعارات الدفع في الخلفية عبر FCM
  لا تُرسل بعد؛ الخدمة تحفظ أحداث الصفقة لكن لا تدّعي تسليم Push.
- يجب إعداد قاعدة البيانات وسر JWT والبريد وHTTPS وحساب المدير وتوقيع APK
  بإعداد إنتاجي قبل إتاحة التطبيقين. مراجعة الاستراتيجية واختبارها تاريخياً
  وواجهة TradingView المضمنة ما زالت من أعمال المرحلة التالية.
